# [![MyBatis](http://www.mybatis.org/images/mybatis-logo.png "mybatis.org")](http://www.mybatis.org/mybatis-3/)
MyBatis acts as a layer between the database and the Java backend. MyBatis generates Java models based on the database schema and generates Java interfaces called mappers which supply Java methods for database operations such as SELECT, INSERT, UPDATE, and DELETE. The Mapper interfaces are backed by XML files with the same name as the mapper, containing SQL scripts which implement the database side of the mapper.

<a name="config"></a>
## Configure Generator
You must configure each table used in the application to be picked up by MyBatis Generator.

The configuration file location: `api/src/main/resources/mybatis-generator-config.xml`

```xml
  <!-- Table Definitions -->
  <table tableName="LK_PERMISSIONS" domainObjectName="LkPermissionDb" schema="APP">
  </table>
  <!-- Tables with an identity column need to have a generatedKey element-->
  <table tableName="USERS" domainObjectName="UserDb" schema="APP">
    <generatedKey column="USER_ID" sqlStatement="JDBC"></generatedKey>
  </table>
  <!-- View Definitions -->
  <table tableName="VW_USER_PERMISSIONS" domainObjectName="UserPermissionVw" schema="APP">
  </table>  
```

Attribute | Use | Best Practice
--- | --- | ---
`tableName` | Name of SQL table from which bean should be generated |
`domainObjectName` | Name of bean to be generated | Tables should always end in Db, Views should awlays end in Vw
`schema` | Database schema of configured database | 
`column` | Identity column of table | This is only needed for tables where the primary key is an IDENTITY/Auto-increment
<a name="run"></a>
## Generate Beans
After configuring a table, or updating the schema of an already configured table, you must (re)generate the Java files.

Run the following command from the api folder:
> mvn mybatis-generator:generate

Generated File | Use
--- | --- 
`___Db.java` | Java model - the fields on this class are one to one with the corresponding database table
`___DbExample.java` | Java class used to represent simple WHERE clauses when using SelectByExample
`___DbMapper.java` | Java interface for performing database operations against the table
`___DbMapper.xml` | XML implementation of the interface

<a name="best"></a>
## Best-Practices
1. You should never modify code generated by MyBatis, as this code will get overwritten every time the generator runs. This includes ___Db.java, ___DbExample.java, ___DbMapper.java, and ___DbMapper.xml.
2. Any custom SQL should go into a custom mapper. 
3. Keep the table configuration entries in order of their table name.
4. All table entries should go directly under their respective comment `Table Definitions` or `View Definitions`

<a name="plugin"></a>
## Generator-Plugins
Sometimes it may be necessary to change the way beans are generated or to be able cover edge cases. If this should occur a plugin can be written to extend how code is generated. Please see the [LBi Core MyBatis Extensions repository](https://bitbucket.lbisoft.com/projects/LCF/repos/lbi-core-mybatis-extensions/browse) for more information.
